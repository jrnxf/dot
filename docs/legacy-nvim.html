The Legacy Neovim Setup

Before the wipe, this repo carried a fully built-out, 11-iteration Neovim configuration: ~45 plugins, a per-server LSP layer with format-on-save, a hand-rolled Lua stdlib, and a hot-reloadable boot pipeline. This page maps what was there, where it lives in git history, and what deserves resurrection into today's minimal lazy.nvim config.

How it died: the three commits that matter

  • 22be109 reference commit

    "nvim restructuring pt11" - the end state of an 11-part restructuring effort. Everything below describes the tree at this commit, under config/nvim/.

  • 58c0037 the wipe · May 4, 2026

    "wipe nvim config, archive old setup as nvim.bak" - the packer-based config had broken against then-current Neovim, so it was shelved to config/nvim.bak and machines started barebones.

  • 39f6a45 gone from the working tree

Recovery is one command away - see the snippet below. The durable version of this page lives at docs/legacy-nvim.md.

Architecture: how it booted

One-line init.lua, then an explicit, documented boot order. The LSP namespace deliberately waited until nvim-lspconfig and all its dependencies were loaded, wired through packer's after/config hooks.

Packer's custom conf handler

A spec entry like { 'folke/trouble.nvim', conf = 'trouble' } auto-expanded to require('jrnxf.plugins.trouble'). Packer is dead, but the one-config-file-per-plugin convention maps 1:1 onto lazy.nvim's plugins/ spec directories.

Hot reload without restart

lib/reload.lua purged every jrnxf.core/jrnxf.plugins module from package.loaded, re-ran bootstrap, then packer.sync(). Bound to F3 and <leader>fr.

The hand-rolled lib/

The most personal part of the setup and the easiest to lose without noticing. None of this is replaceable by a plugin.

The LSP layer

One file per server under lua/jrnxf/lsp/, with shared behavior established in lsp/init.lua. This whole layer is absent from the current config - it is the single biggest gap.

bashls eslint gopls jsonls null_ls prismals pyright rust_analyzer sumneko_lua → lua_ls tsserver → ts_ls

Shared behavior (lsp/init.lua)

  • Rounded borders on every float: diagnostics, hover, signature help, :LspInfo
  • virtual_text = false - diagnostics in gutter + floats, never inline
  • Custom per-severity gutter icons
  • Format on save via a shared LspFormatting augroup, plus <leader>fo and visual-mode <CR> on demand
  • Highlight-references-on-hold, with a documented toggle between vim-illuminate and a plugin-free LSP documentHighlight path

Mason ensure_installed - a census of the languages used

Port this list wholesale; it encodes TS/JS, Go, Python, Lua, Bash, Rust, Prisma, Tailwind.

tailwindcss-language-server pyright html-lsp bash-language-server editorconfig-checker gopls lua-language-server luacheck misspell prettierd shellcheck shfmt stylua typescript-language-server xo

null-ls handled formatting (prettierd, shfmt, stylua), code actions (shellcheck, xo, gitsigns), and the fun hover.dictionary / hover.printenv sources. It is abandoned now - conform.nvim + nvim-lint is the modern path.

Verdict: what to bring over

Today's config is minimal lazy.nvim: snacks.nvim, which-key, gitsigns, neogit, diffview, oil, rose-pine. Ranked gaps, with modern replacements where the old plugin is dead:

1 · biggest gap

LSP + formatting layer

Recreate the per-server layout and format-on-save. Modern stack: nvim-lspconfig + mason (still alive) + conform.nvim + nvim-lint (null-ls is dead). Rename relics: sumneko_lua → lua_ls, tsserver → ts_ls.

2

Mason ensure_installed list

A complete census of languages actually worked in. Port wholesale.

3

Treesitter

Absent today; was foundational. Add ts-context-commentstring back if JSX commenting matters again.

4

Completion + snippets

nvim-cmp or its modern successor blink.cmp; carry the LuaSnip snippets dir - tiny files, pure muscle memory.

5

lib/utils.lua helpers

smart_telescope_files (adapt to snacks.picker), open_url_under_cursor with GitHub shorthand, exec_current_file, put(). Personal tooling - no plugin replaces these.

6

The keymaps

Whole table above, especially the void-register family, c., <leader>gB, fugitive/diffview bindings, window-resize arrows.

7

inc-rename

Live-preview LSP rename. Small, still maintained.

8

Format-on-save discipline

The LspFormatting augroup pattern (or conform's format_on_save) with the <leader>fo escape hatch.

Leave behind

  • packer - dead; lazy.nvim won
  • impatient - built in as vim.loader.enable()
  • feline - unmaintained; snacks/lualine/heirline cover it
  • null-ls - abandoned
  • nvim-tree - oil covers it
  • colorscheme zoo - rose-pine already won
  • cinnamon - Neovim 0.10+ smoothscroll, snacks animations
  • notifier / dressing / nui - snacks.nvim + vim.ui improvements
  • harpoon - only if the workflow itch returns

Judgment calls

  • telescope vs fzf-lua vs snacks.picker - the old config ran both telescope and fzf-lua simultaneously; snacks.picker likely suffices now.
  • trouble - worth re-evaluating (v3 rewrote it) if diagnostics-list workflows come back.
